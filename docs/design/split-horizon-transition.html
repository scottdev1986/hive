00 · Transition basis · interactive technical specification

Hive Workspace UI transition

A build-facing replacement for the original Split Horizon mock. It puts the implemented terminal stack at the center: Hive runs Claude Code, Codex, Grok, Kimi Code, and OpenCode TUIs inside retained zsh sessions, with one selected Ghostty surface attached live. Around that workbench it reconciles communication, memory, quota, Router V3, and Queen’s Hive contracts.

This is a working interaction prototype, not evidence that the screens exist in production. The application mock below is intentionally wired: menus open, all primary routes load, agent selection in the hierarchy sidebar attaches the corresponding vendor’s exact mock zsh generation, inspector tabs and measured agent status change with the selection, all ten routing categories expose five exact vendor settings and editable V3 modes, Queen candidates select, Memory rows filter, scenarios change, drawers open, and consequential commands confirm.

The target remains the existing native AppKit Workspace with HiveTerminalKit. The UI does not introduce a browser runtime, a second daemon, a filesystem crawler, or a classic mode.

The two largest new backend surfaces are explicit. HiveMemory currently has no management projection or UI, and changing the live Queen provider is currently a launch argument rather than a daemon-owned mutation. The mocks name those gaps instead of pretending buttons are contracts.

Source basis: the original Split Horizon plus the six completed or prerequisite maps linked in §01, as present in this repository on 2026-07-27.

01 · System impact

Completed systems change what the UI is allowed to say.

The original Split Horizon correctly chose one live workbench, but its top agent-navigation menu and its Task Routing, token, memory, quota, Queen, message, and run-control surfaces predate the final prerequisite boundaries.

Agent status is a scan layer, not another destination.

The retained hierarchy sidebar shows every agent’s semantic activity as a word, symbol, color, and border. Selecting an agent updates the terminal header and the Session inspector; it does not open an agent screen. The inspector preserves the raw daemon word and the fused session, turn, input, health, attention, source, and freshness facts. Terminal viewer state remains separate: an agent can be working while its terminal is background.

06 · Build order

Freeze facts first, then cut over once.

No phase ships a disabled mock backed by filenames, terminal scraping, guessed state, or a second local store. The pane-era UI remains only a development oracle until its successor passes.

U0

Prerequisite exit audit

Require Router R6 and Hierarchy H5. Re-run the completed terminal, communication, memory, and quota acceptance evidence against the release basis.

  • Freeze topology-neutral identity and exact gate records.
  • Freeze Router inspect/CAS and pool exclusion.
  • Record the token attribution discrepancy as a gap, not assumed completion.
Exit · One versioned dependency manifest names every UI source, owner, freshness rule, and absent state.
U1

Freeze UI contracts and fixtures

Define AppKit client types before production controllers.

  • Workspace, quota, router, Queen, and memory projections.
  • Typed intent/result envelope with CAS, epochs, idempotency, and post-state.
  • Golden fixtures for current, unknown, stale, disconnected, unauthorized, conflicting, and replaced states.
Exit · Every screen in §03 renders exclusively from an immutable fixture; no view reaches files, SQLite, HTTP, or a provider directly.
U2

Native shell and command dispatcher

Build the menu bar, semantic sidebar, screen router, Attention drawer, loading/error banners, and one intent dispatcher.

  • Retain native AppKit window, release packaging, and appearance behavior.
  • Make project/instance context read-only.
  • Separate detach, provider control, terminal termination, node closure, and run control.
Exit · Every menu/shortcut resolves to exactly one command or screen; no retired pane command remains reachable.
U3

Control and management screens

Ship screens that do not depend on terminal rendering.

  • Router V3, Models & Quota, Queen Provider, Autonomy.
  • Memory Overview, Library, Recall Lab, Maintenance.
  • Tokens only if its attribution projection passes; otherwise omit it.
Exit · CAS conflicts preserve drafts, stale reads fence mutations, jobs stream bounded progress, and all final state is read back.
U4

Outer horizon and run control

Render hierarchy, roles/assignments, phases, gates, budgets, attention, reviews, train state, incidents, and run control.

  • Virtualize to the 19-agent target and global 32-session cap.
  • Restore semantic focus/expansion history across snapshots.
  • Show direct, flat, full-hive, lead loss, and ownership transfer.
Exit · No hierarchy fact is derived from a name, pane, terminal line, or provider conversation.
U5

Five-vendor terminal workbench

Connect one HiveTerminalKit surface and make hierarchy-sidebar selection switch the vendor TUI in Live Run.

  • Represent Claude Code, Codex, Grok, Kimi Code, and OpenCode with exact provider, agent, SessionLocator, generation, zsh, and ProviderRun identity.
  • Switch with snapshot/cursor attach, input claim, resize, replay/gap, detach, reconnect, and replacement; never kill the prior session merely because selection moved.
  • Provider stop returns the same PTY to interactive zsh; terminal termination ends the verified tree. Unselected sessions remain typed/event-observed—never fabricated terminal thumbnails.
Exit · One live attachment switches across a real five-vendor matrix from the sole agent sidebar and stays bounded under 19 producers; viewer failure preserves every provider, retained zsh session, and human draft.
U6

Run inspector and contextual recovery

Add Task, Events, and Session panes without introducing Communications, Gates, Review, or Files destinations.

  • Exact task revisions and bounded event/session detail.
  • Communication delivery remains daemon-owned and appears only as contextual Attention when user action is required.
  • Stranded WorkManifest resolution and cascade previews open the affected Live Run context.
Exit · No checklist or status is inferred from terminal text, and no internal message ledger is exposed as a user screen.
U7

Hard cutover and deletion

Ship one Workspace and remove the pane-era surface in the same release.

  • Delete pane grid, master promotion, spatial focus, standalone Settings, old Usage attribution, floating Attention, ProjectSwitcher, old chain editor, strict/spread, and duplicate autonomy command.
  • Delete compatibility reducers, shortcuts, packaging, fixtures, and tests.
  • Keep the native product, terminal kit, CLI non-UI consumers, and daemon ownership.
Exit · The removal ledger is empty, destructive actions read back final state, and no “classic” path launches on failure.
