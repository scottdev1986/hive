00 · Verification basis

HiveMemory

A present-tense map of storage, isolation, ingest, recall, lifecycle, embeddings, tools, configuration, and operator surfaces. Every factual claim carries the rung of evidence that stands behind it and, below the top rung, the exact check that would raise it.

The deployed system is not this source. The running daemon is build 1495d735; git rev-list --count 1495d735..84e58da4 printed 69. The installed CLI is hive 0.0.38 (8ff0a55f, 2026-07-24, darwin-arm64); git rev-list --count 8ff0a55f..84e58da4 printed 102. Every live row below describes those two builds, not this source. The skew is directly observable: hive status on the installed CLI fails to parse the running daemon's reply, rejecting the unrecognized keys holdReason and holdResetAt.

The live memory self-test fails right now. hive memory self-test --live against daemon 1495d735 exits non-zero on semantic-recall. The fix is in this source and has never run live. §8 states the situation at the rungs that apply.

Evidence rungs

  • TESTAn in-process test exercises it. The row names the test.
  • PROCESSA real process, PTY, or signal was exercised. The row names it. This is strictly stronger than test and is never flattened into it.
  • VENDORA real vendor CLI or binary was in the loop. The row names the command and version.
  • LIVEObserved in a running Hive daemon serving real agents.
  • UNPROVENImplemented, with nothing exercising it at any rung. The row names the observation needed.
  • NOT IMPLEMENTEDThe row names the substitute that runs now and the concrete implementation needed.
