HIVE / DESIGN
Messaging v3 · 2026-08-02 · design, not implemented

The terminal belongs to Hive.

The installed vendor remains the agent. Hive becomes the terminal frontend, talks to that runtime through its structured protocol, and can wake it without ever touching the user’s input.

The hard cut

  • Zero automated PTY input—no paste, Enter, key, signal, or composer borrowing.
  • Installed runtime is truth for auth, config, models, tools, permissions, and sessions.
  • Experimental official protocols are allowed; unsupported behavior and native-TUI fallback are not.
  • Claude Channels remain off. No warning spam.

01

One safe process boundary

The useful terminal trick is not a signal or escape sequence. It is refusing to give the vendor process the terminal in the first place.

User terminalKeyboard, paste, mouse, IME and selection reach only the Hive frontend through the sessiond PTY.
→
hive agent-uiOwns renderer, composer, outbound journal, scheduler, command palette and normalized state.
→
Installed vendor childRuns with anonymous pipes or a private socket. Structured prompts, events, approvals and cancellation. Never a controlling TTY.

Automation can wake while you type

The draft, cursor, selection, marked text, history, focus and scroll anchor are frontend state. Provider output can redraw around them but cannot mutate them.

No compatibility escape hatch

A missing protocol produces a branded incompatibility screen. It never launches a native TUI and never types a prompt as a fallback.

03

Delivery is a state machine, not a hopeful write

Publish acceptance, protocol acceptance, turn observation, mailbox claim and settlement are different facts. The UI names each one.

publishedBroker row committed
frontend notifiedRecipient IPC ACK
wake queuedDurable outbound row
vendor acceptedRequest response
turn observedLifecycle event
mail presentedPoll result carried body
mail claimedLease after presentation
settledComplete · defer · reject · dead letter

Idle wake

A recipient-local event schedules a fixed structured prompt immediately—even while a user draft is being edited. It carries an item ID, not message content.

Busy agent

The wake waits for an authoritative turn end, then runs before queued user work. Same-turn steering is deliberately outside v1.

At least once, never false success

An ignored wake retries idempotently until claim or visible terminal failure. A request ACK alone never becomes “delivered.”

04

Status stays orthogonal

An agent can be working, have an active user draft, and have mail waiting at the same time. One status string cannot express that truth.

Fresh structured events become provider-protocol evidence at the current App Server rank. Hook and terminal health remain diagnostic fallbacks. Unknown usage renders —, not 0%, and never gates delivery.

08

Release bars

Maturity labels do not certify behavior. Only a real installed-vendor run can.

Common conformance

  • Initialize with a positive capability control.
  • Create, prompt, observe stream and completion.
  • Allow and deny a harmless permission.
  • Cancel and observe terminal state.
  • Resume/load without duplicate prompt.
  • Discover commands/models/modes where advertised.

User non-interference

  • Wake during typing, paste, IME and selection.
  • Wake during scrollback and resize storms.
  • Crash/reconnect with draft and queue intact.
  • Explicit cancellation never clears draft.
  • Unknown user delivery never auto-retries.
  • Zero non-user calls to terminal input.
09

Bounded open engineering items

None can reopen the no-injection ruling or authorize a native-TUI fallback.

  1. Grok: capture a harmless live ACP permission request and cancel result.
  2. Claude — resolved: use direct stream-json control framing. Live comparison with Agent SDK 0.3.220 proved exact installed-binary use and equivalent initialize/permission events; direct framing avoids adding the SDK's optional bundled-runtime packages.
  3. Journal: choose daemon database or a single frontend-owned SQLite writer after crash/replay measurement.
  4. Marks: pick raster scales and finish the existing asset trademark/license review.
  5. Codex: pin review, compact, model, permissions and status method names from generated 0.146.0 bindings.
  6. Migration: explain the one-time move from native scrollback to a vendor-resumed protocol transcript.
