agent-ui + workspace inspector · design proposal · 2026-08-30

Chat in the pane, everything else in Events

A stricter split than turn folding: the transcript keeps only conversation — user ↔ agent, Queen ↔ agent, and what the Queen says — while every tool call, mail notice, board update and status change goes to the inspector's Events tab. What the agent is doing right now is one line above the composer that rewrites itself and disappears when idle.

The Events tab already exists in the Live Run inspector and is deliberately empty today — ShellInspector.swift refuses to invent a list because no Workspace HTTP GET serves the stream — while the daemon already stores the rows it would show (WorkspaceEventV2 in status_workspace_events). This proposal is the reason to wire that GET.

Both frames are interactive: switch inspector tabs, filter events, and in the Queen frame press Play a mail wake to watch the live line rewrite itself while the Events tab fills and the chat gains exactly one row — ozzie's message.

3 · The rules

Three surfaces, each with one job.

SurfaceCarriesNever carries
Chat (transcript)User messages. Agent replies. Mail between Queen and agent, shown as attributed rows in both panes. Every question or approval put to a person, with its options and the answer given — kept permanently, since an answer is a decision. Diagnostics that need a person.Tool calls, thoughts, mail notices, board updates, status transitions, narration of internal work.
Live lineThe one thing in flight: ◌ Edit · file +n −m, ↳ Mail · work · 1 waiting, ◌ Thinking · 14s. Rewrites in place. Empty and hidden when idle.History. It never grows.
Events (inspector)Everything, typed and timestamped, grouped by turn, wake turns marked, filterable. Rows that produced a chat row say so.Terminal text. Every row is a WorkspaceEventV2, never a scrape.

What this needs in the code

  • A Workspace HTTP GET for StatusStore.listEvents — the inspector's stated missing wire.
  • A chat-projection of mail: inbound items with a body become agent-kind rows attributed to the sender; outbound publishes become replies with a → header.
  • tool, thought, mail, plan entries stop being appended to the transcript and go to the event stream; the live line reads the newest running entry.
  • Wake-origin turns tagged from dispatchedWakes, so Events can group them and the chat can suppress wake narration.
  • ctrl+o focuses the Events tab (or, in a bare terminal without the inspector, opens an in-pane events overlay).

What to watch

  • Bare-terminal users (no Workspace inspector) lose all history of tool activity unless the pane has its own events overlay. Keep one.
  • Error visibility. A failed test or refused tool call is a fact a person may need mid-chat. Proposal: errors the agent does not itself mention within the same turn surface as a chat diagnostic.
  • Attribution. A chat row from bram must be his mail body verbatim, never the Queen's paraphrase; the Events row for it says shown in chat so the two can be reconciled.
  • The Changes exception. Decide once. The toggle above shows both; leaving it to preference means two people describe different UIs.
