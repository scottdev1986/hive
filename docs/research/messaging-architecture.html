Hive architecture research · 1 August 2026

Reliable agent messaging without ever touching the user’s composer

A research-backed reference design for Codex, Claude Code, Kimi Code, Grok Build, and OpenCode. The recommendation is a durable, pull-at-safe-point mailbox over MCP—not terminal paste, simulated keystrokes, Escape, or vendor chat-input injection.

Decision. Make Hive’s daemon the authoritative broker. Persist an envelope before acknowledging a sender; expose it to every agent through the same authenticated MCP mailbox; let the agent consume it only at a declared safe point. A terminal notification may be an optional, user-owned visual indicator, but is never a delivery mechanism and never writes into the composer.
Hard-cutover rule. The new mailbox replaces the old delivery system; it does not sit beside it. Remove terminal notice injection, Escape-based urgency, fallback delivery, legacy message states, and their delivery-attempt code. Hive must have exactly one agent-message path after cutover.

“Stored durably” is not “seen by the model.” “Leased” is not “completed.” The state machine records both.

≤ 1

Every other normal update is summarized or deferred, preventing mailbox-driven context overflow.

Important limit: “zero interruption” and “make a model notice a message immediately” are mutually incompatible for a busy turn. The honest guarantee is durable acceptance now, model-visible consumption at the next safe point. A true emergency stop is a separate, explicit control-plane action with user/user policy—not a disguised message that cancels a user’s work.

What Hive does now, and why it fails

Hive already has valuable foundations: a SQLite/WAL message table, a per-recipient sequence, sender idempotency keys, acknowledgement, and terminal-attempt records. The problem is the final hop: a compact inbox notice is written into a live vendor terminal. Its state notified only proves a transport write, while acknowledged relies on model cooperation.

The repository’s 2026-07-21 incident report establishes the concrete failure: an orphaned user input claim caused sessiond to refuse automation forever, leaving a durable row queued and silent. This was not an isolated bug in one vendor—it demonstrates that a shared user composer cannot be a reliable machine queue.

Interpretation: each vendor has a supported tool/MCP integration surface, so Hive has a portable consumer transport. None offers a common, documented, out-of-band “make the model consume this message without changing its conversation” API. That is why the queue must be external and pull-based.

Reference architecture

Mailbox protocol

ToolContractWhy it matters
hive_mail_publishAuthenticated sender publishes typed envelope with idempotencyKey, lane, topic and TTL. Returns only after durable commit.Sender retry is safe even if it loses the HTTP response.
hive_mail_pollAt a safe point, return at most one control item plus a bounded digest of normal work. Returns cursor and backlog counts, not unlimited bodies.Models get a predictable, small attention budget.
hive_mail_claimAtomically lease one item to recipient-generation + handler id. Lease expires; its receipt is persisted.Crash after receipt produces redelivery, not loss or a wedged “in flight” row.
hive_mail_completeIdempotently settle the claimed item with completed, deferred, or rejected and a bounded reason. Completion effect uses the same idempotency key.Explicit settlement separates “read”, “acted on”, and “needs retry”.
hive_mail_statusRead-only mailbox age, counts, oldest item, lease expiry and DLQ summaries; never sends a model message.Queen can diagnose without becoming another interrupt path.

Delivery semantics and overflow control

Control lane

Typed, small, high-value instructions: ownership transfer, safety hold, reply-needed, shutdown outcome. Strict sequence per recipient + task; max one leased at a time. When full, reject non-critical publishes honestly instead of evicting the oldest.

Work lane

Status/progress updates merge by recipient + sender + topic. Keep last meaningful payload and count/summarize predecessors. A new update replaces stale progress; it does not create a 50-message “chat transcript.”

Dead-letter lane

After bounded retry attempts, schema failure, expired task generation, or explicit rejection, quarantine with reason and correlation IDs. One rate-limited queen alert names the queue; no repetitive notices.

User lane

Completely separate from machine mail. Workspace can show a non-modal badge or inbox panel outside the composer. User typing never creates an automation lease and automation never resolves a user draft.

Implementation plan for Hive

  1. Build the replacement behind an internal test seam. Create immutable mail_events, materialized mail_items, mail_leases, and mail_dead_letters. Implement the new broker and conformance fixtures without wiring a second production delivery route.
  2. Implement the five MCP tools and capability checks. Each request authenticates the recipient subject and agent generation. Validate payload size/type/topic before the transaction. Bind all result effects to messageId.
  3. Add safe-point adapters. Claude and Codex can use their rich hook/event streams; Kimi/OpenCode/Grok use the strongest observed lifecycle event. If an event is absent, polling happens at the next tool invocation or next user-originated turn—never by writing text into the pane.
  4. Perform one atomic cutover. Route hive_send, inbox reads, acknowledgements, escalation and queen traffic to the new broker in one change. If an already-released database must retain unacknowledged mail, copy those rows into mail_items inside the schema transaction and drop the old tables before commit. Do not retain a runtime compatibility reader.
  5. Delete the old system in the same change. Remove SessionSender-based message delivery, flushQueued/flushUrgent notice delivery, Escape dispatch, formatNotice, terminal message-attempt schemas/tables, queued → notified → acknowledged semantics, stuck-terminal retries, and every flag or branch that could reactivate them. Keep terminal input only where it serves an unrelated lifecycle function such as a vendor’s initial kickoff.
  6. Make the launch instructions explicit. Agents receive a small rule: check the bounded mailbox at safe points, claim only one control item, settle it before resuming work, and do not poll in a tight loop. This is behavior guidance; broker capacity limits are the actual safety net.
  7. Ship observability with the cutover. Per recipient: oldest unleased age, oldest leased age, backlog by lane, coalesced count, redeliveries and DLQ count. Queen receives one deduplicated alert only when an SLO breach begins. A build-time removal check prevents message-delivery code from importing the terminal-input layer.
Do not use queue depth as a prompt to interrupt. It is a congestion signal. Coalesce/defer ordinary information, throttle noisy publishers, and surface health in a dashboard. Escalate only typed safety or ownership events, through an explicit control policy.
